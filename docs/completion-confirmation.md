# 個別の完了確認（1.2.40 公開前候補）

対象の作業名、変更前の状態、Google照会時の件名と保存状態、実施日を一つのダイアログで確認して確定する。対象IDは詳細で確認できる。実施日は空欄を許可し、今日の日付や入金状態を推測しない。件名の目印だけでは保存状態を変更しない。

Googleの同一カレンダーID・予定ID・分類・ETag・本人設定を照合し、原文を端末履歴に保存して読み戻してから If-Match 付き PATCH を送る。Googleの再GETで完了情報と保持情報を検証し、端末保存の読み戻しまで成功した場合だけ成功を表示する。別の端末編集は削除せず、変更前の編集も履歴へ残す。認証scope、同期、保存機構、金融記録は変更しない。

送信後に応答が不明な場合、同じ画面の「保存結果を再確認」はGETだけを行い、追加PATCHを送らない。一致しない場合は未完了として扱わず、結果未確認を表示する。競合時は閉じて再同期し、改めて個別に確認する。Google照合後に端末保存が失敗した場合は、その段階を表示する。処理中の二重クリックとEscapeによる閉鎖を止め、ページを離れる場合はブラウザの通常の確認を利用する。端末やブラウザの強制終了を防ぐものではない。

## 診断

旧1.2.39の変更していないコードと合成応答で、通常保存・IndexedDBポインタ保存・QuotaExceeded退避保存を確認した。いずれも日付入力後の確定まで進めば成功した。`saving` を無条件に原因とする根拠はない。旧UIは日付promptと別のconfirmが必要で、失敗説明は離れた共通ステータスに表示される。警告が残ることだけで確定・認証・保存のどの段階だったかは特定できない。

旧コードはGoogle完了時に対象の `edits` 全体を削除していた。今回、完了関連フィールドだけを置き換え、別の編集情報を保持する。これは合成の未知フィールドと件名編集の保持でも検証した。
