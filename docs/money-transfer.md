# 口座間振替（1.2.55候補・未公開）

銀行を操作せず、確認済みの口座間移動を記録する。1振替＝1記録であり、入金と支払の2記録にはしない。`kind:transfer`、`transfer:{date,amount,from:{label,reference},to:{label,reference},evidence:{status,note,ref?}}` に両側を保持する。正の整数額、実日付、異なる正規化済み口座参照、確認根拠が必須。口座参照は操作者が同一口座を同じ値へ照合する必要があり、口座名だけの自動同定はしない。

確認済み振替だけが対象。`done:true` は確認済みを表し、通常の消込済みバッジは付けない。`actuals:[]`（架空の収支実績を作らない）、`subjectMonth:null`（対象外）、plannedDate/Amountは振替日/額と一致する。月内収支、未消込累計、ホーム・予定の通常入出金から除外。お金画面の「口座間振替」に選択月で表示し、入出金・消込フィルターとは独立。履歴・口座・根拠を読める。一般の編集／実績／消込操作は禁止。振替訂正・取消の専用手順は今回の範囲外。

## 書込み経路

既存 `scripts/batch-money-ledger.cjs` の plan → prepare → verify を再利用。requests に `{transfer:{...}}` を指定する。日時・操作ID・本人・台帳・全履歴checkpoint・全差分の承認を固定する。2回の独立読取、保存直前再照合、既存コネクタによる履歴タブへのRAW1封筒行追記、2回全体読戻しが必要。CLI自身は通信しない。本番への追記は未実施。

固定記録IDは `transfer:<operationId>:<index>`。同じ操作の確認済み再試行は append:null。同日・同額・同じ出金元/入金先は別IDでも停止し、同額別口座は別取引として扱う。同条件で実際に複数回送金した場合も自動登録せず別途確認する。結果不明時は同じ封筒IDを先に読み戻す。基準から変更・破損・隔離・競合があれば停止。全子履歴の検証前に一部を適用しない。Google Sheetsの原子的排他は保証しない。

## 旧端末と本番前提

1.2.54は振替を含む封筒を丸ごと隔離し、batchIssueCountにより編集を停止する。収支への偽装や無言の読み捨てはしないが、新状態を表示できない。**対応版を公開し、稼働中の全端末・旧タブを更新、未送信編集を同期して同じcheckpointを確認するまで追記しない。** 現行運用ではFold/Flip両端末について `money-transfer-v1` の実確認が必要。compatibleReadersは証拠の記録であり機械的な版検知や認証ではない。架空の証拠を本番へ使わない。

旧公開bundleは不変。古い版へ戻すだけでは新しい振替履歴を読めなくなるため、追記後の単純な版戻しは不可。履歴削除によるロールバックもしない。

## 独立レビュー追補

独立担当が振替→通常収支変換のP1を指摘。UIの値だけの判定では複数head競合を防げなかったため、履歴全体で汎用編集/resolveを禁止し、changeとanalyzeの両境界でも振替の後続変更を停止。振替は専用batch内create・親なしに限定。照合表示も対象月「対象外」、状態「振替確認済み」、実日付・額・根拠へ統一。

旧版は編集を止めても通常同期中に別の未送信履歴や比較を送る可能性がある。旧端末混在を許容するものではない。全旧タブ終了と両端末の対応版・未送信編集照合は本番前提。

訂正・取消は初回の確認済み振替登録自体には必須ではないが、登録後の誤りを即時修正できない制約がある。事前に両側口座・日付・額・根拠・重複を確認した限定運用のみ。後日誤りが判明したら停止し、別途履歴保全型の訂正設計が必要。通常編集、撤回、偽の逆振替、履歴削除では代用しない。銀行で実際に別の逆送金が行われた場合だけ独立した振替として別途確認する。
