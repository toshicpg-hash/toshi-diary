# 端末の隔離履歴：1.2.50

Google側だけ正常でも、端末にGoogleにはない隔離履歴があれば同期成功にしない。最初の読取りと端末への原本保持後、Googleへの追記前に停止し、再読取り時にも確認する。

## 原本を残す明示的な処置

`hub-money-quarantine.js` は書込みなしの計画を作る。対象はSHA列が欠けた7列の旧settle操作だけ。有効履歴がGoogleの独立2読取りと完全一致し、旧操作の親が現在headで、変更内容がdone=falseからtrueだけ、実績は空である場合に限定する。未送信の有効編集、別の変更、競合、Googleの変化があれば停止する。欠けたSHAを補完したり、旧操作を有効化したりしない。

画面は「接続・バックアップ・同期状況」→「同期状況・元の記録・バックアップ」→「隔離原本の保管計画を確認」。私用の処置ファイルを選び、対象・予定額・理由・正式反映待ち／別途確認を一画面で確認する。取消なら保存しない。確認後にGoogleを再度2回読み、全ローカル原本も同一IndexedDBトランザクションで照合してから、旧イベントの完全な保存単位をメタデータへ保管し、活動中の隔離一覧から移す。Googleへの書込みはない。

処置ファイルの架空例：
```json
{"format":"papa-money-quarantine-decisions","operationId":"synthetic-recovery","decisions":[{"revisionId":"synthetic-invalid","disposition":"awaiting-formal","replacementOperationId":"synthetic-formal","reason":"旧操作は採用せず、確認済み実績を別の正式操作で反映"}]}
```

別件は `disposition: "separate-review"` とし、replacementOperationIdを指定しない。別件の有効な元予定は未消込のまま集計する。原本保管は消込ではない。保管だけで「支払済み」にしない。

保管は固定operationId、計画hash、原本hash、承認と保存日時を持つ。再試行は同一内容なら追記しない。保管内容が違う、原本が再侵入した、保存結果が不明な場合は停止し読戻す。失敗時に別IDでやり直さない。通常のお金保全バックアップに保管領域を含み、新版の復元でも完全性・同一キーの競合を確認する。元の保全ファイルも保持する。旧版へのダウングレード復元では保管領域の維持を保証しないため行わない。

固定した正式バッチが後日読戻されたとき、その子履歴と親・記録IDを照合して対応を表示する。実績の日付・額・口座・根拠、現在の消込状態と実績保持も確認し、後続の取消・変更を完了扱いしない。分類月や銀行照合を推測しない。端末の原本保管と、正式バッチのGoogle保存・両端末照合は別段階。

## 運用順と限界

公開承認・通常更新後、対象端末で処置ファイル選択と1回の確認を行い、同期する。両端末の対応版・最新checkpoint・未送信編集なしを実確認した後だけ、別途承認済みの固定金融バッチを実行し、全体2回読戻しと両端末への反映を確認する。compatibleReadersを推測で埋めない。本機能はサイトデータ削除・再移行・設定変更を不要とするが、利用者端末への遠隔適用はしない。

実行した試験は架空データだけ。実機操作、Google実接続での原本保管、本番金融追記は未実施。提供された旧6操作の抽出内容は照合できたが、元ファイルの厳密な直列化バイトはローカル取得できていない。処置計画は適用端末の実際の原本から計算し、再構成したデータを代用しない。

`scripts/plan-money-quarantine-recovery.cjs` は別用途の読み取り専用診断で、既にGoogleにある同じID・先頭7列完全一致のコピーだけを候補にする。今回の別settle操作には適用できず、原本保管の代替手段ではない。
