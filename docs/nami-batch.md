# 承認済み一括操作（1.2.49候補・未公開）

`scripts/batch-money-ledger.cjs` はネットワークや銀行を操作しない予行・照合 CLI。実機の対応版、未送信編集の同期、同じ基準 checkpoint の確認が揃うまで本番実行しない。`compatibleReaders` は実確認の記録であり、CLI が確認を代行するものではない。両端末に `money-batch-v1` 対応版が必要。

## 手順

1. 本人・台帳を確定し、既存設定・全履歴・比較等を独立に2回読み取る。両端末の同期を区切り、対応版と同じ checkpoint を実確認する。
2. `node scripts/batch-money-ledger.cjs plan input.json > plan.json`。既存ID、現在head、全差分、対象外履歴、固定操作IDを凍結する。
3. 全変更を本人承認と照合する。承認には planHash、operationId、owner、ledgerId、日時と説明を固定する。ハッシュは完全性照合であり署名・本人認証ではない。
4. 保存直前に再取得し、`node scripts/batch-money-ledger.cjs prepare fresh.json plan.json`。変更があれば停止。出力は履歴タブに追記する1行だけ。既存の許可済みコネクタで RAW として追記する。
5. 全体を独立に2回読み戻し、`node scripts/batch-money-ledger.cjs verify readback.json plan.json`。基準履歴＋同じ封筒1行、全対象、対象外、設定・比較・照合表示の不変を確認。結果不明なら元操作IDを読み戻す。別IDで再送しない。
6. Google保存確認と両端末の同期・表示確認を分ける。全バッチ終了後に端末照合する。別バッチへ古い確認を流用しない。

## 分離と分類保留

既知区分・既知額・実績なし・未消込の1予定を2～5項目へ分離できる。最初の項目は元ID、追加項目は操作IDから固定したIDを使う。合計予定額の完全一致、元head、理由、全内訳を `splitOrigin` に保存する。実口座・実績は各項目別に確認する。元履歴を削除せず、疑似実績で相殺しない。既存実績ありの分離は対象外。

実績日・金額・口座・根拠が確定していれば、請求対象月が不明でも明示した分類保留理由付きで消込可能。`subjectMonth:null` は保持する。日付から月を推測しない。区分未確認はこの例外に含めない。画面は「入出金は消込済み・請求対象月の分類は保留」と表示し、消込と分類を区別する。

## 一括性と限界

最大20改訂、JSONセル全体40,000文字。全変更を1封筒行に保存し、全子改訂の検証成功後だけ表示へ展開する。容量超過は停止し、自動分割しない。Sheetsの原子的排他を保証しない。競合・破損・部分結果は成功扱いにせず、封筒の一部だけを採用しない。子改訂は単独追記しない。

旧1.2.48は新封筒を未確認として隔離し、変更前の値を保持する。最新版の集計になる互換性はないため、旧端末が混在した運用は禁止。破損封筒では変更前の参考表示と警告を出し、編集を止める。公開済み旧bundleは変更しない。
